递归自我改进：从一杯咖啡到Harness Engineering

递归自我改进：从一杯咖啡到Harness Engineering 2025年夏天，我去美国纽约和波士顿做短期访问，回程途经旧金山转机。我决定在旧金山多呆一天——去之前通过邮件约了几位朋友，其中包括素未谋面的Lilian Weng。 我乘地铁去了OpenAI当时的那栋小白楼。他们楼下有一家星巴克，我在那儿等她。那是下午两点，店里坐满了人，一半以上的屏幕上开着代码编辑器，邻桌在讨论transformer的注意力机制，角落里有人在白板上画架构图。你能清晰地感觉到，这栋楼里正在发生什么。 后面和Weng之间的AI讨论故事不多说了——言归正传。我当时记住了一句话：“模型本身不是瓶颈，真正的瓶颈是我们怎么让模型更好地使用工具、管理上下文、持续进化。” 今年7月4日，她在博客上发表了那篇《Harness Engineering for Self-Improvement》，结合随后官宣加盟OPRNAI的消息，我才意识到那天那句话的分量。这篇文章，我想从技术的角度，拆解她到底看到了什么。 一、RSI：一个60年的概念，为什么现在才可行 Lilian Weng的文章开篇直接切入主题：递归自我改进（Recursive Self-Improvement, RSI）。 这个概念可以追溯到1965年，英国数学家I. J. Good提出的"超智能机器"——一种能在所有智力活动中超越人类，并设计出比自身更好的机器的系统。2008年，Eliezer Yudkowsky将这个概念精确化为一个反馈循环：AI利用其当前的智能，去改进产生其智能的认知机制。 听起来很抽象。但Lilian Weng把这个抽象概念落到了实处。她指出，在现代AI语境下，这个反馈循环可以发生在三个层面： 模型权重层面：模型直接重写自己的参数。这是最理想但最难的路径，目前几乎不可行。 训练管道层面：模型改进生成训练数据、选择训练任务、优化训练策略。这是很多前沿实验室正在探索的方向。 部署系统层面：模型改进自己与外界交互的方式——如何调用工具、如何管理上下文、如何评估自身输出。 她明确选择了第三个切入点。原因很关键：原始模型和真实世界之间的这层，其重要性不亚于模型本身的原始智能。Claude Code和Codex的成功，不是因为它们的基础模型最强，而是因为它们的部署系统设计最成熟。 她用了一个词来描述这层部署系统：Harness。 二、Harness：模型与世界之间的操作系统 “Lilian Weng在咖啡馆里用了一个比喻，“我回忆道，“她说Harness就像操作系统。你花在操作系统上的功夫，决定了CPU能发挥多大潜力。” 在她的定义中，Harness是围绕在基础模型周围的整个系统，它负责： 编排执行流程（模型如何思考和规划） 定义工具调用（模型如何与外界交互） 管理上下文（模型感知和存储什么信息） 持久化产物（模型如何保存工作成果） 评估结果（如何判断模型表现好坏） 这个定义的精妙之处在于，它将原本分散的概念——Prompt Engineering、Agent Framework、Tool Use、Memory Management、Evaluation——统一到了一个更宏观的架构视角下。 更重要的是，她指出了Harness工程与传统Agent框架的区别： 维度 传统Agent框架 Harness工程 核心公式 agent = LLM + memory + tools + planning + action 额外加入workflow design, evaluation, permission control, persistent state 设计理念 Prompt模板 运行时系统设计 类比 IDE 操作系统 这个类比不是随便说的。Lilian Weng明确指出，Harness的设计应该参考操作系统的工程实践： ...
