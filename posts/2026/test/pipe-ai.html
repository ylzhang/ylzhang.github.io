二、规划建设、电力衡算与 Token 产出（硬约束与敏感性）

本节将「机柜数量 × 单柜 IT 功率」与「站级用电量」对齐，并给出 Token 产出与收入的区间化测算。所有乘除可在 Excel 复核；若与可研不一致，以可研为准。

2.1 规划装机与 IT 总功率（算术校正）

分区 机柜数 单柜 IT 功率 分区 IT 功率
风冷通用计算区（规划） 2,500 12 kW 30.0 MW
液冷高密度推理/训练区（规划） 6,000 21 kW 126.0 MW
合计（名义 IT） 8,500 — 156.0 MW

口径说明：2,500×12 kW + 6,000×21 kW = 156 MW（IT）。若对外沟通使用「约 160MW 级」，应解释为规划余量、网络与存储 overhead、或后续小幅扩容，并在同一页披露 156MW 基准算术，避免投资人复核时发现不一致。

2.2 年满负荷 / 半负荷电力（站级）

站级用电量 = IT 功率 × PUE × 时间。风冷与液冷分区 PUE 差异显著，下表采用假设区间（可替换为设计值）：风冷区 PUE 1.22–1.32；液冷区 PUE 1.08–1.14（不含极端气候与调试期）。

场景 风冷区站级功率（假设） 液冷区站级功率（假设） 合计站级功率（约）
满负荷（IT 100% 铭牌） 30×1.27 ≈ 38.1 MW 126×1.11 ≈ 139.9 MW ≈ 178 MW
半负荷（IT 平均 50% 利用，辅助负载部分跟随） 工程上常将站级电量近似为满负荷的 55%–68%（固定损耗占比上升） ≈ 98–121 MW 年均等效（需负荷仿真）
运营情景 估算年用电量（亿 kWh） 测算式（说明）
满负荷连续运行（简化） 约 15.6 178 MW × 8,760 h ≈ 1.56×109 kWh；实际运行率 <100%，应乘以可用性系数
半负荷（取站级 60% 等效） 约 9.3–10.5 15.6 × 0.60–0.67 粗算；最终以8760小时负荷曲线为准

电费敏感性（仅能源 OPEX，不含折旧）：若综合电价 0.28–0.42 元/kWh，则满负荷年电费约 4.4–6.5 亿元；半负荷约 2.6–4.4 亿元。此数字不包含 GPU/加速芯片折旧、资金成本与网络费用。

资本开支现实检验（与「总投资 50 亿元」对齐）：仅 156MW IT 的机电、土建、外电与冷却，若以行业常见的每 IT kW 8–15 万元人民币（不含芯片）粗算，土建+机电已是约 125–234 亿元量级；加速芯片与网络通常另计且波动极大。因此，「50 亿元」在工程上不足以独立完成本文规划的满配机柜与芯片填充，应明确为：首期股本金 + 撬动地方产投 / 项目贷 / 设备融资租赁 / 客户预付款的组合；或下调首阶段交付机柜规模。若向红杉、真格等机构呈现，建议单列「资本金 / 总 program」两张表，避免被现场拆穿算术。

2.3 「有效 Token」产出：假设、区间与不可承诺事项

Token 产出由模型结构、批大小、精度、SLA、并发、缓存命中率与集群网络共同决定，无法用单一常数描述。对投资人更诚实的做法是给出可替换参数的敏感性表，而不是一个「精确到个位」的伪科学数字。

参数 基准假设（可改） 备注
用于 Token 生产的 IT 功率占比 55%–70% of 156 MW 余量含存储、网络、管理与波谷
输出 Token 强度（示意） 每 1 MW 有效 IT：0.8×1014–4×1014 output tokens/年 对应不同模型与利用率；需用目标模型在目标硬件上的 benchmark 替换
可计费 Token 比例 70%–95% 内部测试、故障切换、赠额会稀释「可开票」部分

在上述示意参数下，年化输出 Token（量级）大致落在 约 6×1015–4×1016（即约 6000–40000 万亿 output tokens/年）的宽区间内。任何窄区间承诺均需要已锁定的芯片型号、模型清单与 SLA 合同支撑。

2.5 项目价值叙事建议（对 IC 友好）

  • 单位经济：同时披露「每 MW IT 的年电费」「每 MW IT 的折旧+利息」「每百万 tokens 的边际成本」三类曲线。

十、融资与财务规划：资本金与总 program 拆分

10.1 两本账：股本金 vs 总 program

账本 含义 本材料中的示意规模

依赖「开源模型 + 微调」进入市场：客观 SWOT

不训练闭源基础模型、以开源权重 + 垂直微调切入，是资本效率较高的路径，但与 hyperscaler 自研栈竞争时，需在材料中主动披露边界。

内容（理性表述）
优势（S） 上市速度快：可基于 Llama/Qwen/Mistral 等生态快速交付推理与 Agent；研发摊销低于从头预训练；易与国产芯片栈做联合适配；便于向客户展示「可迁移、可审计」的模型血缘。
劣势（W） 同质化：开源权重人人可用，议价权更多来自运维、时延、合规、行业数据与 SLA而非模型独占；顶尖能力滞后于闭源前沿；品牌上易被归类为「套壳」除非工程指标过硬。
机会（O） 政企与金融更偏好私有化与可控链路；「东数西算」电价差支撑推理工厂；开源工具链（vLLM、SGLang 等）降低软件门槛；可与云厂商形成「他们做平台、PIPE-AI 做专用产能」的分工。
威胁（T） 云厂商降价与打包销售；许可证变更（开源协议、商用条款）；出口管制导致高端 GPU 波动；客户自建集群；电价与碳排政策收紧。

给 IC 的结论句：PIPE-AI 的护城河应写成「单位 Token 的可靠交付成本 + 合同可见度 + 合规交付记录」，而不是「拥有某开源模型的独占权」。

核心公式

  • Revenue = Tokens per Watt × Available Gigawatts
    收入 = 每瓦Token产量 × 可用吉瓦数
  • Profit = (Token Price - Token Cost) × Token Volume
    利润 = (Token单价 - Token成本) × Token产量
  • Tokens/Watt = Total Tokens / Total Power Consumption

结语：可验证的重资产叙事

PIPE-AI 的叙事若要在红杉、真格等机构面前成立，核心不是「Token 即货币」的修辞，而是三件事：（1）装机与电力是否对得上账；（2）资本金与总 program 是否拆得清；（3）开源+微调路径下，单位经济是否经得起与 CRWV、NBIS 等公开标的的对照。本版材料已将 156MW IT 的算术、分区 PUE、年满负荷/半负荷电量区间、以及 50 亿元股本金的边界写在前排，便于你们直接挑战假设。
