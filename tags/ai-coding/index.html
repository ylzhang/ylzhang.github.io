龙虾大会：一场关于AI编程的集体幻觉

【发稿人按】 三月的第一个周末，上海张江某栋写字楼的会议室里坐满了人。他们不是来参加什么新产品发布会，而是为了学习如何使用一个开源工具——OpenClaw。这个在GitHub上收获超过27万颗星星的项目1，在过去两个月里从一个技术社区的小众项目，变成了整个中国AI圈最火热的话题。从北京中关村到深圳南山，类似的聚会几乎每周都在上演，这场被称为"龙虾大会"的运动，正在以一种近乎狂热的姿态席卷整个行业。 但作为发稿人，我必须提出第一个质疑：**这场大会究竟在解决什么问题？**当演讲者们反复演示如何用几句自然语言生成一个待办事项应用时，这些场景与真正复杂的软件工程之间，还隔着一条难以逾越的鸿沟。本文试图穿透表象，探讨工具迭代与模型升级之间的深层关系。 那些坐在会议室里的开发者们带着各自的期待而来——有人希望找到下一个创业风口，有人想提升自己的编程效率，也有人单纯被"AI替代程序员"的焦虑驱动。然而，当舞台上的演示从精心设计的demo切换到真实的业务场景，面对遗留系统的技术债务、模糊的产品需求、严格的合规要求时，AI的表现就会迅速退化为一个偶尔能提供代码补全建议的辅助工具。 【专业审稿人批注】 这里需要明确一个技术本质：当前AI编程工具的核心仍是基于概率的模式匹配系统。它们在处理常见编程模式、标准库调用、以及有明确边界的任务时表现出色，因为这些场景在训练数据中有充足的样本。但一旦涉及到需要深度领域知识、复杂架构设计、或者跨系统集成的任务，AI就会暴露出理解力的局限。 更重要的是，编程从来不只是写代码——它还包括理解业务逻辑、权衡技术方案、与团队协作、以及在约束条件下做出工程决策。这些软技能，恰恰是当前的AI最难以替代的部分。那些在龙虾大会上被反复强调的"生产力提升"，很大程度上只是将编码阶段的部分工作自动化，而软件开发的全生命周期中，编码往往只占不到三分之一的工作量。 这种认知落差并非偶然。云服务厂商和模型公司的热情参与，让这场运动变得更加复杂。对他们来说，OpenClaw提供了一个绝佳的切入点：通过简化部署流程、提供托管服务，他们可以将开发者锁定在自己的生态系统中。一键部署听起来很美好，但它也意味着用户将基础设施的控制权交给了平台；Token计费模式看似灵活，但当应用规模扩大时，成本可能会变得难以预测。 **这些商业模式的设计，更多地反映了供应商的利益，而非用户的真实需求。**当所有人都急于在这个新兴市场占据一席之地时，关于"这些工具究竟能创造什么价值"的冷静思考反而被边缘化了。 【普通审稿人反馈】 说实话，我参加过一次这样的大会，感觉就像是在听一场"AI万能"的布道。演示的时候确实很惊艳，但回到公司试了一下，发现生成的代码根本跑不通，或者跑通了也不知道为什么会跑通。那种兴奋感很快就变成了困惑——这玩意儿到底能不能用在真正的项目上？ 我同意文章里说的，现在的AI编程工具更像是"高级代码补全"，而不是真的能理解我在做什么。最讽刺的是，那些大会上讲得最热闹的人，往往不是真正在写代码的人。 这种过热的状态很难持久。历史经验表明，技术 hype 的周期通常在六到八周达到顶峰，随后进入冷静期。龙虾大会也不例外。当最初的兴奋消退，当参会者们回到自己的工位尝试将这些工具应用到实际项目中，他们会发现现实的骨感：AI生成的代码可能需要大量的修改才能运行，自动化的工作流可能在边界情况下崩溃，而那些被承诺的"十倍效率提升"在复杂项目中变得难以兑现。 三到八周后，当再有人提起龙虾大会时，语气中可能会带着一丝怀念，更多的是一种"那阵子大家都挺疯狂的"的调侃。 但这并不意味着AI编程工具没有价值。恰恰相反，它们在某些场景下确实能显著提升效率——尤其是在原型开发、学习编程、以及处理重复性编码任务时。问题在于，当前的市场叙事将这些能力过度放大，试图用"AI替代程序员"的惊悚标题来吸引眼球，而忽视了工具能力的边界。 【专业审稿人批注】 这里必须引入一个关键视角：工具的迭代与底层模型的升级密切相关。OpenClaw、Cursor这类工具本质上是Agent的落地表现形式，而Agent的能力边界直接受制于底层大模型的能力。 2026年2月17日，Anthropic发布了Claude Sonnet 4.6，在代码理解和生成能力上有了显著提升2。这不仅是性能基准的升级，更重新定义了这个赛道的天花板。当模型能够更好地理解复杂指令、处理长上下文、进行多步骤推理时，建立在它之上的编程工具才能获得质的飞跃。 **换言之，工具的演化是模型演化的函数。**没有底层模型的突破，单纯的工具创新很快就会触顶。 来自大洋彼岸的一些信号值得我们关注。在Claude Sonnet 4.6发布后，Cursor作为目前AI编程工具赛道的领导者，明显感受到了前所未有的压力。这种压力不仅来自模型能力的跃升，更来自竞争格局的剧变——当底层模型公司开始直接提供强大的编程能力时，中间层工具的护城河在哪里？ **据业内人士透露，Cursor内部已经将这种状态定义为"战时模式"。**这并非空穴来风：从2026年2月到3月，Cursor连续发布了自动化工作流、JetBrains IDE支持、自主计算机控制等多项重大功能3，这种密集的产品发布节奏本身就说明了一切。即便是市场领导者，也必须在模型快速迭代的背景下不断进化，否则随时可能被淘汰。 【发稿人按】 “战时模式"这个表述值得玩味。它暗示了一个残酷的现实：在AI编程工具的赛道上，没有永恒的安全区。当Anthropic这样的模型公司推出更强大的编程能力时，Cursor必须在产品层面做出回应，否则用户就会直接转向模型原生的解决方案。 这也解释了为什么龙虾大会的火热某种程度上是焦虑驱动的——开发者们担心错过下一个风口，服务商们担心被时代抛弃，创业者们则在寻找能够抵御模型公司直接竞争的商业逻辑。 更深层的观察是，龙虾大会的火热某种程度上反映了当前大模型落地的困境。经过两年多的发展，模型能力的提升并没有自动转化为生产力的飞跃。C端应用除了ChatGPT之外鲜有成功的案例，B端落地则面临着数据安全、成本效益、组织变革等多重障碍。 在这种情况下，编程成为了一个相对容易切入的场景：开发者本身就是技术早期采用者，代码是结构化的数据，效果可以通过自动化测试来验证。但即便如此，真正的生产级应用仍然寥寥无几。大多数尝试停留在个人项目或内部工具层面，难以支撑起规模化的商业模式。 【普通审稿人反馈】 我觉得文章里说的"困境"很真实。我们公司也尝试过用这些工具，但最后发现，真正省时间的不是让AI写代码，而是让AI帮忙写文档、写测试、或者解释一段看不懂的祖传代码。 可能AI编程工具的价值不在于"替代程序员”，而在于"帮程序员做那些他们不想做的事"。但这样的话，市场规模就没那么大了，估值也就没那么高了。所以那些大会上的演讲者肯定不会这么讲。 这种困境并非中国独有，但在国内表现得尤为明显。一方面，基础模型的能力与国际顶尖水平仍有差距，这限制了应用层面的创新空间；另一方面，市场的急功近利心态让很少有人愿意沉下心来打磨产品，大家都在追逐短期的热点和概念。 当OpenClaw火了，所有人都在谈论OpenClaw；当下一个框架出现，注意力又会迅速转移。在这种环境下，真正的技术积累和产品迭代变得困难，大部分参与者只是在不同的热点之间疲于奔命。 【专业审稿人批注】 文章结尾需要回到一个核心判断：工具的迭代是不可逆的，但工具的形态是可变的。OpenClaw可能只是一个阶段性的产物，就像早期的jQuery、后来的React，技术的演进会让今天的"龙虾大会"变成明天的历史注脚。 真正重要的是，在这个工具快速迭代、模型持续升级的时代，什么是相对稳定的——可能是对软件工程本质的理解，可能是对业务逻辑的把握，也可能是人机协作的新范式。找到这些"不变量"，比追逐当下的热点更有价值。 回到最开始的问题：究竟是谁在玩龙虾？答案可能是：那些焦虑的开发者，试图在这个快速变化的时代找到安全感；那些投机的服务商，希望借助热点推销自己的产品和服务；那些迷茫的创业者，在寻找下一个可能的风口；以及那些真诚相信技术能改变世界的理想主义者，尽管他们中的大多数最终会发现，改变比想象中要困难得多。 这些人共同构成了这场运动的参与者，也共同承受着期望与现实之间的落差。当热潮退去，真正有价值的东西会留下来。可能是一些被验证过的最佳实践，可能是几段在特定场景下确实能提升效率的工作流，也可能是关于"如何与AI协作"的新认知。 但前提是，参与者们能够从这场集体的狂热中抽离出来，诚实地评估工具的能力边界，并在实际的业务场景中寻找真正的价值创造点。这需要时间，需要耐心，也需要一定程度的运气。 而在那之前，龙虾大会还会继续，只是参会者脸上的表情可能会从兴奋变成困惑，再从困惑变成一种若有所思的平静。那可能是一个更健康的状态——对于技术，对于行业，对于所有在其中寻找机会的人来说，都是如此。 【发稿人终审】 本文通过三个视角的交叉审视，试图呈现龙虾大会背后的多重真相。这不是一篇唱衰AI编程工具的文章，而是一篇提醒人们保持清醒的文章。在模型快速迭代、工具不断演化的今天，唯一不变的是变化本身。如何在变化中找到价值，是每一个参与者都需要回答的问题。 参考 OpenClaw GitHub Repository, https://github.com/openclaw/openclaw,
